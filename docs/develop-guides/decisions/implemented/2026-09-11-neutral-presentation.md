# 公共项目的中性展示

状态：implemented
类型：simplification
Owner：backend/package/yuxi/config/static/info.template.yaml

## 问题

页面、默认智能体身份和文档站带有原项目名称、图形标识、个人推广及默认归属文案，不适合作为公共知识工作区。

## 决策

默认展示使用“知识工作台”和通用窗口图标，移除原作者推广请求、Star 卡片、品牌图片和默认版权页脚。仅部署者显式填写的版权配置在首页展示。默认智能体使用通用助手身份；CLI 的展示文案和包描述采用中性名称。Web 帮助入口使用当前仓库文档生成的站内页面，build、dev 和 server 命令生成内容，Docker 同步提供文档输入。文档站首页由 `docs/.vitepress/theme/components/HomePage.vue` 拥有，Pages 从实际仓库推导部署路径。

源码包名、环境变量、命令入口、协议头、存储目录与数据库标识继续作为兼容接口存在。许可证与第三方版权声明保留。

## 替代方案

- 保留现状：无法满足中性展示要求。
- 仅修改标题：推广入口、模型身份和文档仍带品牌。
- 全量重命名运行接口：需要迁移现有配置、包导入和持久数据。
- 清除对外归属展示：覆盖页面、模型和文档入口，保持运行兼容。

## 后果

产品默认不依赖原作者的推广网站或图片服务。站内帮助由文档生成，维护者更新文档后重启开发服务器或重新构建即可同步。既有部署的自定义 YAML、用户保存的提示词和历史对话属于部署数据，不由源码清理覆盖。源码路径与现有命令中的兼容标识不表示页面归属。
